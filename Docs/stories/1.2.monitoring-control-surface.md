# Story 1.2: Monitoring Control Surface

## Status
Draft

## Story
**As a** desktop user who relies on OptiGemini for network stability,
**I want** intuitive start, stop, and pause controls in the main window and system tray,
**so that** I can manage monitoring sessions without command-line interaction.

## Acceptance Criteria
1. Main window exposes Start, Stop, and Pause buttons that reflect current monitoring state within 1 second of user action.
2. PowerShell engine responds to Start/Stop/Pause commands received from the WPF layer without leaving orphaned runspaces.
3. System tray context menu mirrors the same controls and stays in sync even when the window is closed or minimized.
4. Each action writes an INFO log entry with timestamp and new state, visible in the inline log viewer.

## Tasks / Subtasks
- [ ] Design WPF command bindings for Start/Stop/Pause buttons with visual states (AC: 1)
  - [ ] Disable inappropriate actions based on MonitoringService state (AC: 1)
- [ ] Implement MonitoringService methods to relay commands to PowerShell bridge (AC: 2)
  - [ ] Ensure `Engine.Runspace.Hosted` flag toggles are respected (AC: 2)
  - [ ] Add cancellation token handling for Pause scenario (AC: 2)
- [ ] Wire tray icon context menu to shared command infrastructure (AC: 3)
  - [ ] Add toast notification when monitoring resumes from tray (AC: 3)
- [ ] Extend logging pipeline to record button events with state transitions (AC: 4)
  - [ ] Surface log entries in Logs tab and Execution Console (AC: 4)
- [ ] Create safety tag and push branch mirror to `backup` remote prior to review (AC: 1-4)
